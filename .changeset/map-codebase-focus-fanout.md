**Map-codebase focus-area fan-out (ADR 0013 rollout).** `/gsd:map-codebase` now fans the 4 focus-area mappers — tech / arch / quality / concerns — out through a new `dynamic-workflows/gsd-map-codebase-fanout.js` workflow when the Workflow tool is available (Claude Code). Unlike the code-review / verify fan-outs (whose agents write nothing), each mapper here writes its own 1-2 `.planning/codebase/*.md` docs directly — a deliberate, scoped exception to ADR 0013 D2's read-only rule, justified by the disjoint-filename invariant: the 4 focus areas map to 7 non-overlapping filenames, so even under the Workflow tool's no-op worktree isolation there is zero file collision and no branch runs a test process (collision-free). Each branch returns `{focus, status, files:[{file, lines}]}` via schema — never document bodies — so the orchestrator preserves map-codebase's context-saving design (it never ingests doc text). A hard load-time assertion (and `tests/map-codebase-fanout.test.cjs`) proves the focus areas' filename sets stay pairwise disjoint. The orchestrator stays the single writer for the commit and keeps all interactive gates (`check_existing` Refresh/Update/Skip, `scan_for_secrets`). When the Workflow tool is unavailable (Codex, Gemini CLI, Antigravity), the workflow falls through to the verbatim `sequential_mapping` path. The win is determinism/consistency, not wall-clock — map-codebase was already parallel. See `docs/adr/0013-dynamic-workflow-parallelization.md` §Rollout template.
