**SDK git-backed execution engine → production behind a config gate (ADR 0013 option 3).** The SDK phase runner had an `ExecutionEngineFactory` seam that production never injected, so headless `gsd-sdk` runs took a no-op execution path: every plan ran in the shared project cwd, merges were faked, and the build+test gate always returned `testExit=0` — bypassing invariant 3. This wires the REAL engine (`GitWorktreeManager` + `GitMergeSerializer`) into production behind a new opt-in config gate `git.sdk_worktree_execution` (default `false`, Claude runtime only per inv-12). When on, `GSD.runPhase` builds the factory via a new `sdk/src/build-execution-engine.ts`, which runs a **fail-closed worktree-capability pre-flight** (`git worktree add --detach` off HEAD, asserts a LINKED worktree, removes it) that **THROWS** rather than ever silently falling back to the no-op engine — a silent fallback would run concurrent shared-tree mutation and bypass inv-3. Plans then run in per-plan worktrees with a single-writer merge serializer and a **real build+test gate**: `git.sdk_test_command` if set, else `npm test` when a `package.json` test script exists, run via execFile in the post-merge protected checkout (timeout → exit 124, inconclusive ≠ pass). A `worktrees.create()` failure under the isolated engine is now **fatal** (the plan is marked failed) instead of degrading to shared cwd, gated by an `isolated` discriminator on the engine. Default `false` preserves today's no-op path byte-for-byte; fully reversible by flipping the flag. See `docs/adr/0013-dynamic-workflow-parallelization.md` §"The DAG protocol — SDK surface".
