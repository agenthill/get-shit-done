**Dynamic-workflow parallelization of phase execution (POC).** GSD execution now expresses the true per-plan `depends_on` DAG instead of coarse wave-level barriers, and the read-only post-execution gate chain runs as a deterministic dynamic workflow. A new `dag-runspec` query exposes the direct dependency edges (previously computed then discarded) plus `files_modified` serialization edges. The SDK's `runExecuteStep` replaces its `Promise.allSettled` wave barrier with a promise-per-plan DAG (concurrency cap + worktree-per-plan + single-writer MergeSerializer, with the per-plan merge decoupled from a per-level batched build+test gate); no-op collaborators preserve today's behavior by default. The interactive `/gsd:execute-phase` fires Agent-tool executors over the ready set (multiple in one message — the `.git/config.lock` stagger is gone) with fork-off-predecessor `EXPECTED_BASE` and per-plan topological integration (guard suite verbatim). A new `dynamic-workflows/gsd-verify-fanout.js` runs the post-execution gates (static goal verify, code review, prior-phase regression, schema-drift, codebase-drift) concurrently, collapsing the serial chain from sum→max. All 14 preservation invariants (atomic commits, STATE.md single-writer, test-gated completion, worktree safety, interactive gates) are preserved.
