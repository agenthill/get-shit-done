**Plan-phase CHECK-stage read-only fan-out (ADR 0013 rollout).** `/gsd:plan-phase`'s plan-check stage (step 10) now fans the gsd-plan-checker dimensions out through a new `dynamic-workflows/gsd-plan-check-fanout.js` workflow when the Workflow tool is available (Claude Code): one read-only branch per PLAN.md runs the per-plan dimensions (task completeness, scope, must_haves derivation, key links, context / CLAUDE.md / tier / pattern compliance, scope-reduction, per-task Nyquist presence) and one cross-plan branch runs the whole-phase dimensions (requirement + decision coverage, dependency graph / cycles, cross-plan data contracts, Wave-0 cross-reference + sampling continuity, research resolution, shared-pattern presence). Every branch returns BLOCKER/WARNING findings via schema and writes nothing — collision-free under the Workflow tool's no-op worktree isolation because gsd-plan-checker is static plan analysis (Read/Bash/Glob/Grep, no Write, no test process). The orchestrator stays the single writer for STATE.md / ROADMAP.md / the plan commit, aggregates the verdict, and drives the revision loop; plan AUTHORING stays serial on the Agent tool (the gsd-planner revision spawn writes PLAN.md files). On a re-check (revision loop or `--bounce`), the orchestrator scopes the per-plan branches to the plans it changed via `git diff` against the pre-revision tree (fallback: all) while always re-running the cross-plan branch over the full set. When the Workflow tool is unavailable (Codex, Gemini CLI, Antigravity), the workflow falls through to the verbatim single whole-set gsd-plan-checker agent (today's behavior, runtime-gated like code-review.md). The win is collapsing the serial whole-set check from sum → max(slowest-plan-branch, cross-plan). See `docs/adr/0013-dynamic-workflow-parallelization.md` §Rollout template.
